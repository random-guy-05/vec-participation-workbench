Community Release Notes Builder

Explain a public tool update in terms a participant can use: who benefits, what changed, whether anything breaks, and what is still limited.

Be clear about what changed for the user, not only which files changed.

Release notes that build trust

State verification evidence and limitations honestly. Link challenge-specific facts to current official pages. Do not announce a change as available until its public version is reachable.
