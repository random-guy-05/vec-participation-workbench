Source Overlap Audit

Find exact sample or cell identifiers that recur within one source or across sources before combining datasets. Review possible overlaps against the source records; this tool never removes rows or decides whether reuse is allowed.

Paste an identifier manifest

Use two CSV columns named source and id. Each row is one sample or cell identifier. Keep identifier values as text so leading zeros are preserved.

Case folding can create false matches for case-sensitive identifiers. Turn it on only when the source conventions support it. No fuzzy matching or alias inference is performed.

Paste a manifest or load the synthetic example, then audit it.

Interpret the report

  • Cross-source candidate: the same normalized identifier appears under two or more source labels. Confirm that the identifiers refer to the same kind of entity before treating it as an overlap.
  • Repeated within source: an identifier occurs on multiple rows under one source. These may be duplicate records, repeated measurements, or a valid source design.
  • Identifiers absent from one or both columns are skipped and counted. The report is a review queue, not a deletion list, data-use ruling, or proof of leakage.

Processing stays in this browser tab. Nothing is uploaded, stored, or sent to a server. Use public or synthetic manifests and follow the Challenge's current rules for external-data eligibility and disclosure.
