Sparse Matrix Footprint Estimator

Compare dense, CSR, CSC, and COO numeric payload sizes from a matrix shape and stored nonzero count before choosing an in-memory representation.

Matrix and storage assumptions

Enter nnz as the number of stored values in the matrix you plan to load, not a percent. The copy count is your planning scenario for simultaneous copies of that same representation.

Change the defaults or choose the example, then estimate.

What the estimate includes

  • Dense payload: rows × columns × bytes per value.
  • CSR payload: values and column indices for each stored entry, plus a row-pointer array.
  • CSC payload: values and row indices for each stored entry, plus a column-pointer array.
  • COO payload: values and two indices for each stored entry.

These are raw array payload estimates, not peak RAM or on-disk H5AD size. They omit compression, object metadata, other AnnData slots, allocator overhead, index conversions, and temporary arrays. Actual readers may keep multiple copies; the selected copy factor is only a scenario, not a prediction.

Inputs stay in this browser tab. Nothing is uploaded, stored, or fetched. Use matrix dimensions and counts, never private data.
